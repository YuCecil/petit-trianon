# 小特里亞儂｜網站規則（版面、插圖、真實圖片、網站程式、手機檢查）

> 從 CLAUDE.md 拆出來的細則。改版面、做插圖、放真實圖片、改網站程式、跑手機檢查之前讀這份；只寫故事、資料卡時不必讀。跟 CLAUDE.md 衝突時以 CLAUDE.md 為準。

## 8. 網站風格：「小特里亞儂」（使用者 2026-11-15 選定）

設計概念：小特里亞儂是王后躲開凡爾賽禮儀的私人小宮殿。網站像一套擺在那裡的**塞弗爾（Sèvres）瓷器**：每個故事是一只盤子，盤緣是當年瓷器廠真實的釉色。**主題世界觀只用在外框**（開場、故事目錄的盤子、迷思判定章），**閱讀欄保持安靜**。使用者說過目前精緻度還不夠，要慢慢修；修改時參考戰時餐桌的完成度。

- **語氣**：像一個很會講故事的朋友在咖啡館跟你聊。短句、口語、有畫面；不寫論文腔，也不寫八卦週刊腔。不嘲笑當事人，也不替他們翻案；讓史料說話。專有名詞第一次出現時用括號解釋。
- **用字**：繁體中文、臺灣用語；年代用西元。
- **配色**（`docs/assets/style.css` 的 `:root`，新增元件只用這些變數）：奶油紙 `--paper #FBF7F0`、內頁 `--sheet #FFFDF8`、深灰藍墨水 `--ink #2E3A4B`、次要文字 `--muted`、線 `--line`。**鍍金 `--gilt` 是稀有色**：只用在盤子的金邊、迷思判定章、圖表 `highlight`、目前選中的項目。
- **分類釉色**（瓷器廠當年的釉色名稱，是網站顏色的依據）。每類有 `-glaze`（盤緣、色塊）與 `-ink`（文字，對紙張 ≥4.5:1）：

  | category | key | 釉色 |
  |---|---|---|
  | 迷思 | `myth` | 國王藍 bleu de roi |
  | 生平 | `life` | 天藍 bleu céleste |
  | 宮廷 | `court` | 蘋果綠 vert pomme |
  | 時尚 | `mode` | 龐巴度粉 rose Pompadour |
  | 飲食 | `table` | 黃水仙 jaune jonquille |
  | 人物 | `people` | 紫羅蘭 violet |
  | 革命 | `rev` | 鉛灰 |
  | 身後 | `after` | 灰玫瑰 |

  元件加 `data-cat="myth"` 等就會自動套色。**新增分類**要同時改 `style.css`、`app.js` 的 `CATS`、`tools/lint.py` 的清單、本節表格，並算過對比。
- **字體**：標題、數字、引文用 Cormorant Garamond（西文）＋ Noto Serif TC（中文）；內文用 Noto Sans TC。不加第三種字體。
- **版面**：靠左對齊。閱讀欄寬 `--measure: 680px`。區塊之間用留白和 1px 細線分隔，不用陰影。**唯一的「卡片」是故事盤子**（首頁故事目錄，以及故事結尾的「接著讀」）。故事頁、名詞頁、資料卡都是單欄，相關資訊放在文章最後的 `<aside class="page-info">`。
- **迷思判定元件**：故事頁的「流傳的說法／史料怎麼說／判定章」對照框；故事目錄的盤子下方顯示判定；獨立頁「迷思對照」列出所有有 `verdict` 的故事。
- **首頁**：開場（標題、導言、分類、吉祥物）→ 故事目錄（依分類分組，每個故事一只盤子）→ 更多（連到各獨立頁）。頂端選單每一項都是獨立頁面（迷思對照、時間軸、地圖、數字、研究爭論、資料庫、關於）；唯一例外是「故事」，連到首頁的目錄。
- **時間軸**：照年份分組的直式清單，可依分類篩選；1789-07-14（攻占巴士底）插一條分隔線。
- **地圖**：觸控板、手機雙指都可以縮放。
- **動態**：只回應使用者操作（滑過盤子時輕轉）。尊重 `prefers-reduced-motion`。
- **手機**：寬度 375px 時不可以橫向捲動。
- **長文閱讀（2026-11-16 參考報導者、端傳媒、BBC、The Guardian、NYT 的長文版面，使用者同意）**：
  - 頂欄往下捲時收起、往上捲出現；手機頂欄只留一行（標誌＋「選單」按鈕），選單點開才展開。
  - 內文字級：電腦 18px、手機 17px，行高 1.85。
  - 手機上故事首圖與內文插圖貼齊螢幕左右。
  - 故事有 3 個以上小標時，除了文內「本文段落」，捲過之後右下角出現浮動「目錄」按鈕，標出目前讀到的小節；讀到文末自動收起。
  - 故事結尾「接著讀」：最多 3 只盤子，先放這篇提到的其他故事，不夠再補同分類的。
  - 寬螢幕（≥1180px）右側空白當旁註欄：點開的註釋、插圖與真實圖片的圖說都顯示在段落旁邊。
- **3D 立體地圖（2026-11-16 試做，使用者同意；參考報導者的互動模組）**：故事裡寫 `{{3d:trianon}}`。先顯示盤子造型的海報與「開始互動」按鈕，按了才從 cdnjs 載入 three.js 0.160.0 與 `docs/assets/trianon3d.js`（省流量、不擋捲動）。
  - 場景資料 `docs/assets/trianon3d.json` 由 `python3 tools/trianon3d.py` 產生：建築與水域輪廓取自 OpenStreetMap（原始檔在 `raw/maps/`，網站要標 © OpenStreetMap contributors，ODbL）；地名標記寫在 `data/trianon3d-spots.json`，每一點都要有 `topic` 與 `source`，說明文字只能用故事裡已有出處的內容。
  - 圖說要寫明：建築是今天的輪廓、高度是示意。地名互相擋住時自動縮成小圓點。
  - 改了 `trianon3d.js` 或場景資料，把 `app.js` 的 `S3D_V` 加一。

### 8.1 禁止清單

- 盤子以外的卡片牆、卡片裡再放卡片、陰影、大圓角（例外：盤子本身是圓的；地圖彈出框沿用 Leaflet）。
- 標題上方的小標籤（eyebrow）、徽章。
- 超過 1px 的彩色側邊條。故事頁頁首上方的那條釉色橫線是唯一例外。
- emoji 或 Unicode 符號當圖示；需要圖示就畫 SVG。
- 漸層文字、毛玻璃、光暈、裝飾性條紋背景、洛可可花邊、皇冠與百合花紋（fleur-de-lis）裝飾。
- 彈跳緩動；每個區塊都一樣的淡入。
- 「大數字＋小標籤＋強調色」的數據卡。
- 中文標題切在詞中間：標題用「主標：副標」格式，`app.js` 的 `phrase()` 在「：？，」分段。
- 跳過標題層級；每頁剛好一個 `h1`。
- 低對比：文字至少 4.5:1，大字與圖形至少 3:1。

### 8.2 插圖（一律用 Gemini 生成，使用者不自己動手）

- **工具**：Gemini，透過 **Claude in Chrome** 在使用者的瀏覽器開新分頁操作。生成和修圖（改局部、去背、統一畫風）都用 Gemini。網站的小圖示（favicon）等向量圖，由主 session 照 Gemini 的圖描成簡化 SVG。
- **分工**：提示詞一律由**主 session 親自寫**（使用者認為品質較好）。操作 Gemini（開分頁、貼提示詞、下載、存檔）可以派一個 Haiku，**提示詞要原封不動照貼，不可自己改寫**；一次只派一個。存檔後主 session 打開圖檢查（畫風、內容是否符合出處、有沒有文字或錯字、手指與臉有沒有崩壞），不行就寫修改提示詞再生。
- **畫風**：只用一種：「18 世紀粉彩速寫風」——奶油色紙底、柔和的粉彩與淡水彩筆觸、線條輕、留白多，配色限本站釉色（國王藍、天藍、蘋果綠、龐巴度粉、黃水仙、紫羅蘭）加少量鍍金。提示詞模板見 `templates/illustration-prompt.md`。新圖要跟既有插圖放在一起比過，風格一致才用。
- **真實人物**：不畫成可辨識的寫實肖像（容易被誤當成史料）。國王、王后等人物出現時，用遠景、背影、側影或剪影；優先畫物件與場景（蛋糕、裙子、馬車、宮殿房間、信紙）。
- **內容**：場景要對應頁面裡有出處的內容。不加「AI 生成」之類的備註。畫面不要有文字。
- **位置**：首頁開場、每個故事頁頁首（有圖才放）、404 頁；每個故事的「故事是這樣的」裡最多再放一張內文插圖，語法 `{{img:<故事id>-2.jpg|一句話說明畫面}}`。另外可以放**最多 4 張真實圖片**（當時的畫作、版畫、文件、今日照片），語法 `{{photo:<檔名>|說明|來源與授權}}`，見 8.5。資料卡、名詞頁、問答頁不放圖。
- **檔案**：原圖存 `raw/images/`；網站用 `docs/assets/img/<故事id>.jpg`，寬 1000px、品質 70（`sips -Z 1000 -s format jpeg -s formatOptions 70`）。
- **站名**：「小特里亞儂」＋副標「瑪麗．安東尼與路易十六」。

### 8.4 註釋（參考報導者的排版）

- 內文裡的出處 `（[[s-...]] 頁 x）` 由 `app.js` 自動轉成上標註號 ¹ ² ³，放在句末標點後面，並和前一個字綁在一起不換行（標點、註號都不會單獨落到行首）；點了會展開那一條出處（手機在原地，寬螢幕在右側旁註欄）；全部註釋集中在文末「註釋」區，預設收合。讀者讀內文時不會被出處打斷。
- 寫作時照舊在段落最後標出處，不需要自己編號。同一段有多個出處就寫在同一個括號裡，用「；」分開。
- 括號裡不是出處的說明文字（例如「（推論）」「（本站譯）」）照樣留在內文。

### 8.5 真實圖片

- 只用**公有領域或 CC 授權**的圖：優先 Wikimedia Commons（畫作、版畫、照片），也可用博物館的開放取用圖（例如凡爾賽宮、大都會博物館 Open Access、Gallica 的公有領域版畫）。每張都要記下來源網址與授權。
- 存檔：`docs/assets/photo/<故事id>-<關鍵字>.jpg`，寬 1200px 以內、品質 75；原始網址與授權記在 `data/photos.json`（`{"file", "title", "creator", "date", "source", "license", "topic"}`）。
- 圖說寫：畫了什麼、誰畫的、哪一年、現藏何處，例如「維傑．勒布倫，《穿襯衣裙的瑪麗．安東尼》，1783 年，德國黑森邦基金會藏」。來源與授權寫在圖說最後的小字。
- 真實圖片不受 8.2「不畫真實人物肖像」的限制（那條是限制 AI 生成的插圖）。

### 8.3 吉祥物：王后的小狗

- 一隻小狗，是網站的導覽員，語氣同第 8 節。**造型（2026-11-15 定案）**：小巧的巴哥犬（pug），淺杏色短毛、黑色臉部面罩、捲起的小尾巴，脖子繫國王藍（#2E4F98）緞帶蝴蝶結、中間一顆小金鈕扣，大眼睛、表情溫和好奇；18 世紀粉彩速寫風。每次生成都把這整段貼進提示詞。原圖在 `raw/images/mascot-*.png`。
- 「王后嫁到法國時被迫在邊境跟小狗分開」是流傳的說法，**真假要查證**，查證結果寫成故事頁，吉祥物的介紹以查證結果為準。
- **只出現在三個地方**：首頁開場、關於頁、404 頁。故事頁、目錄、圖表不放；**革命與身後的頁面絕對不放**。一頁最多一隻。
- 檔案（去背透明 PNG，寬不超過 520px）：首頁 `mascot.png`、關於頁 `mascot-about.png`、404 `mascot-404.png`。

## 9. 網站程式

- 純靜態網站，不用打包工具。`docs/index.html` + `docs/assets/style.css` + `docs/assets/app.js`，另有 `docs/404.html`、`docs/favicon.svg`。
- 外部函式庫只從 cdnjs 載入、寫死版本：marked、Leaflet、Chart.js、vis-network。字體從 Google Fonts。
- 路由：`#/`（首頁）、`#/p/<id>`、`#/myths`、`#/timeline`、`#/map`、`#/numbers`、`#/debates`、`#/graph`、`#/library`、`#/about`。新增 wiki 頁面**不需要改網站程式**，只要跑 `build.py`。
- 改了 `style.css` 或 `app.js`，要把 `index.html` 裡的 `?v=數字` 加一。
- 改了版面，要用瀏覽器實際檢查首頁、一個故事頁、一個獨立頁；桌機看一次，主控台沒有錯誤。可以在背景用 headless Chrome 截圖檢查，不跳視窗：`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=1280,2400 --screenshot=<暫存區>/x.png <網址>`。
- **手機檢查（朋友用 iPhone 17 看，2026-11-16 使用者要求列為標準流程）**：改了版面（不論大小）、或新增／大改故事後，跑 `node tools/mobile_check.mjs --shots <暫存區>/mobile`，結果要是 **0 錯誤**。它用 WebKit（跟 iPhone Safari 同一套核心）模擬 **iPhone 17**（402×874），打開所有獨立頁、每一篇故事、各類型一頁與 404 頁，檢查：左右滑動、圖片或檔案載入失敗、程式錯誤（以上算錯誤）；字小於 12px、按鈕或可點的註碼小於 24×24px（WCAG 2.2，算提醒，能修就修）。使用者決定只測 iPhone 17，大改版也一樣，不再測 iPhone SE、Android。跑完要打開截圖（首頁、瓦雷納、時間軸、地圖、迷思對照）親眼看過。加 `--lighthouse` 會再跑 Google Lighthouse 的無障礙評分（用本機 Chrome），低於 90 也算錯誤。
  - 工具裝在專案的 `.tools/`（`cd .tools && npm install playwright-core lighthouse && npx playwright-core install webkit`，不上傳 GitHub；WebKit 核心存在 `~/Library/Caches/ms-playwright`）。新環境沒有 `.tools/` 時先照這行安裝。
  - 這仍然是模擬，不是真機；朋友回報的問題以朋友的手機為準。
- 有 Node.js 時，用 Impeccable 偵測器掃描（`python3 -m http.server 8791 -d docs` 後 `npx impeccable detect "http://localhost:8791/#/"`），結果要是 0 個問題。
